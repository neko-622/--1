01项目总览

本项目是针对「智能物流搬运」赛项开发的物流小车车载下位机固件，运行在 STM32F407 主控板上。车辆的机械部分由 麦轮移动底盘 与一套 塔吊式抓取机构（偏航旋转 + 升降 + 吊臂伸缩 + 夹爪）构成；电控部分以本固件为核心，协调各路传感器、执行机构与外部视觉设备。

系统可工作在两种模式：

  • 自动模式 control_mode = 0：按 Main_task 中预设的 预赛/决赛 流程自主完成「出库 → 扫码取任务 → 抓取/放置物料 → 码垛/转盘放置」。
  • 遥控模式 control_mode = 1：由遥控器（DMA 串口）接管底盘与塔吊，进行调试/人工干预。拨杆 L1 切换接管、按键 L1 NVIC_SystemReset() 远程复位、L2 跳过初始化。
核心能力：绝对坐标场地定位（OPS）、二维码/色环/物料/物料盘视觉识别（Nano + 视觉指令协作）、麦轮运动学底盘闭环、3 轴塔吊运动控制与抓取动作序列。

04FreeRTOS 任务与调度

任务在 freertos.c 的 MX_FREERTOS_Init() 中创建，伴随 3 条串口接收消息队列。

任务优先级栈(字)入口 → 实际运行职责
UART_RX_TASKAboveNormal256×4UART_RX_Task → UART_RX_Task()从 3 条队列取指针，分发解包（OPS/RC/Nano）
CHASSIS_TASKNormal128×4Chassis_Task → Chassis_task()底盘电机控制环（每 ~5ms）
TOWER_TASKNormal1128×4Tower_Task → Tower_task()塔吊三轴电机控制环（每 ~10ms）
defaultTaskNormal128×4StartDefaultTask占位空任务
MAIN_TASKBelowNormal256×4Main_Task → Main_task()比赛编排：其阻塞等待动作序列完成，得以调度其他任务
OUTPU_TASKLow128×4Output_Task → Output_task()OLED 状态显示、就绪倒计时
协调机制：任务间主要通过 全局状态标志 与 共享结构体 协作（非消息队列），例如 ready / chassis_mode / control_mode / in_pos / near_pos / v_in_pos / SpeedTarget[4] / VIS_RX。串口中断→ DMA 缓冲 → 队列 → UART_RX_TASK 解包 → 供各任务读取，是主要的事件传递路径。

05关键数据结构

struct RC_DATA Remote_Control_RX.h

遥控器状态。两摇杆 LX LY RX RY、两旋钮 KNOB_L/R、四按键、四拨杆，均 int8_t。RC_CONNECT_FLAG 连接标志。

经 RC_Data_Unpack() 从 UART5 帧 [FA][..][FB] 填充；拨杆 L1 → control_mode。

struct VISUAL_DATA visual_identity.h

Nano 视觉返回数据。三色物料坐标（r/g/b_block_x/y）、色环 rgb_circle_x/y/z（z=左减右，用于偏航）、物料盘中心 tray_center_x/y、block_grab 抓取指令、block_order 决赛摆放顺序。全部 short。

全局实例 VIS_RX，由 NANO_Data_Unpack() 逐 case 填充。

globals in main.c 共享的全局状态

pos_x / pos_y / zangle / xangle / yangle / w_z：OPS 位姿（元/度/角速度）；SpeedTarget[4]：四电机目标速度；color_task[6]：6 个任务位（预赛 3 轮 ×2 / 决赛两轮），由 OPENMV 或 二维码填充；circle_x/y[3]：色环基准坐标。

UARTx_RX_TypeDef main.h · struct Finish_Flag tower.h

前：DMA 接收缓冲结构（buffer[] + size），3 个串口各配 5 份环形缓冲。后：塔吊三电机初始化完成标志 MOTOR35_flag / MOTOR28_flag / G6220_flag，由 CAN 反馈回写。

06核心函数说明

主编排 Main_task.c

void Main_init() void

初始化软SPI OLED、清屏、显示方向，进入 visual_idle()，并复位 OPS 坐标 pos_reset()。

void Get_Task_Code() void

扫描阶段循环调用 identify_QR_code() 直到 color_task[0]+color_task[5]!=0；带超时（80 次）无结果时切换二维码朝向 d_X 以改变视角；完成后 visual_idle() 并清零底盘逼近量。

void CRing_Dual_Calibration() void

色环双重校准：先 Chassis_Visual_Pos(4,…) 粗校准 + identify_posture()，再 Chassis_Visual_Pos(2,…) 精校准，最终保证底盘对位精度。

void Main_task() void

比赛主流程。初始化→显示版本→等待 ready→蜂鸣→复位位姿→等启动按键→置 chassis_mode=1。随后按 #ifdef __PRELIMINARY_ROUND__ 编译分支执行 预赛 或 决赛 两轮流程，每轮都以上一组固定路径点（物品台→粗加工→码垛区→转盘）串起所有抓取/放置动作，结束下令 chassis_mode=2 停机。PRE 默认预赛代码。

底盘任务与运动学 Chassis_task.c / chassis_control.c

void Chassis_Go_Pos(x,y,z,precise,delay) void

阻塞式场地定位。写目标并置场地环；按 precise 等待 near_pos(接近) 或 in_pos(就位)，随后按需延时。

void Chassis_Visual_Pos(target,x,y,z,delay) void

视觉定位子流程。chassis_mode=2 解除场地环，关电机，向 Nano 请求对应目标（物料盘/色环/码垛色环/粗校准），循环直至收到数据，再用 visual_pos_adj() 闭环，v_in_pos 就位后蜂鸣复位。

void chassis_move(x,y,z) void

麦轮位置环。由 OPS 位姿计算 devx/devy/devz，经 cos/sin 投影与分段限幅速度解算 4 轮速度，叠加每拍 ±20 加速斜率以平滑，并更新 near_pos/in_pos 标志。

void visual_pos_adj(target,x,y,z) void

视觉细闭环。将 Nano 给出的目标坐标与设定像素差的偏差转换为速度（vKp），按目标编号不同的死区/就位阈值累计 delay_visual，超阈值置 v_in_pos=1。

void SetMotorVoltageAndDirection(m1..m4) void

把四路目标速度编码为 8 字节驱动命令帧，经 UART4 依次发送给 4 台 42 闭环步进电机驱动器（含方向位）。

速度系数 0.238 把内部速度量映射为驱动器指令。

void Chassis_task() void (RTOS 主循环)

按 control_mode/chassis_mode 选择：场地环、视觉停机、或遥控 chassis_RC()，最后统一 SetMotorVoltageAndDirection() 输出，周期 5ms。

塔吊 Tower_task.c / tower.c

void Tower_target_updata(radius,height,theta) void

塔吊三轴目标：radius=28 吊臂、height=35 升降、theta=G6220 偏航角（单位：0.1°）。

void Tower_task() void (RTOS 主循环)

每 ~10ms 对三轴电机做位置控制。遥控模式下由 RC_RX.KNOB 直接映射到 28(伸缩) 与 35(升降)。

void track_materials(color) void

物料跟踪。利用 Nano 的物料像素偏移累加 d_radius/d_X/d_Y 逼近量（带限幅），并累计达到指定阈值后置 t_in_pos=1，配合底盘做动态抓取。

塔吊动作函数族

grab_turntable_B(物料台动态抓) / grab_materials_ground(地面抓) / put_materials_ground(地面放/码垛) / grab_materials_car(车上抓) / put_materials_car(_right)(车上放) / put_block_turntable + put_turntable_action(决赛转盘放)。每个动作 = 设置塔吊目标序列 + 阶段延时 + 夹爪开合（LFD_01M_* 宏）。

void G6220_Position / Motor35_AbsPosition / Motor28_AbsPosition etc.

底层电机控制：G6220 用 float 弧度 + 速度经 CAN 发送；35 步进换算 z*MOTOR35_Reduction 脉冲数；28 步进换算 y*MOTOR28_Reduction，均含机械范围限幅（claw_h_max/min, claw_r_max/min）。

位姿与视觉 position.c / visual_identity.c

void POS_Data_Unpack(rec[32]) void

解析 OPS 28 字节帧（帧头 0D 0A、帧尾 0A 0D），用 union 把 24 字节直接映射为 6 个 float（zangle/xangle/yangle/pos_x/pos_y/w_z）。

void Update_OPS / Update_X/Y/Z void

通过 UART2 向 OPS 发送 ACT0(复位) 与 ACTX/Y/J+float 进行站位信息校准。光标坐标系更新用 Stract 拼接。

void NANO_Data_Unpack(frame[16]) / OPENMV_Data_Unpack() void

Nano 16 字节帧按首字节 0x66、尾校验 0x77 分 case 解包至 VIS_RX；二维码结果 case=9 写入 color_task。OPENMV 帧 0x88 起始、六数和=12，写 color_task。

HDL 函数 (freertos.c / main.c)

void MX_FREERTOS_Init()

创建 3 条队列（各 4 元素、存指针）与 6 个任务线程。

void USART2/5/1_DMAHandler()

三个串口共用的“空闲中断 + DMA”接收：IDLE 时停止 DMA、记录长度、投递缓冲指针到队列、轮转缓冲下标、重启 DMA。在 USART2/5_IRQHandler / USART1_IRQHandler 内被调用（stm32f4xx_it.c）。

07通信接口与协议

接口对象方向/协议要点
USART1视觉 NanoMCU→Nano 4字节指令[0x66, 任务码, 目标, 和校验]；Nano→MCU 16字节帧[0x66, case, data…, 0x77]。任务码：0 空闲 / 1 物料盘 / 2 物料 / 3 色环 / 8 码垛色环 / 9 二维码 / 6 决赛放置 / 7 抓取指令。
USART2OPS 定位OPS→MCU 28字节位姿帧(0D0A…0A0D)→6 float；MCU→OPS 命令：ACT0 复位、ACTX/Y/J+float 坐标更新；printf 重定向到此。
UART4底盘 4×步进电机MCU→每台 8字节命令帧（含地址/方向/速度）。阻塞发送 4 条。
UART5遥控接收机16字节帧[0xFA, 摇杆/旋钮/按键/拨杆…, 0xFB]，解到 RC_DATA。
CAN1塔吊电机G6220 偏航（标准ID 0x100+trim 偏移 / 0x101 等，float 弧度+转速）、35 步进(ExtID 0x300)、28 步进(ExtID 0x400)。回零 0x9A02 006B；超 8 字节命令分包 Can_SendCmd()。
SPI1 / 软SPI双 OLEDOutput 用硬件 SPI1；Main 用 GPIO 拉时序软 SPI，均 1.3' 128×64。
GPIO/TIM1I/OLED_1/2/3(PB5/4/3)、蜂鸣器(PC0)、补光灯(PD1)、电机总开关VM_SW(PD0)、启动按键(PD3)；TIM1 CH1 输出 MG90 夹爪 PWM，不同 LFD_01M_* 开度对应不同开合幅度。

08中断与 DMA 机制

  • 串口接收（空闲中断+DMA）：USART1/2/5 各自映射 DMA 流：UART5=DM1 Stream0、UART2=DM1 Stream5、UART1=DM2 Stream2。IDLE 中断里停止 DMA → 记录长度 → 缓冲指针入队 → 轮转 → 重启 DMA；UART_RX_TASK 从队列取指针解包。
  • CAN1：CAN_RxFifo0MsgPendingCallback 读帧并交给 Response_Handle() 更新 flag（认证电机就位）。
  • 时钟基：TIM4 周期中断 → HAL_IncTick()；TIM2 用作延时（htim2，delay_us）。
  • 系统时钟：HSE 8MHz → PLL(4/168/2) → SYSCLK 168MHz，APB2/2、APB1/4。

09依赖关系

模块调用方向（大致自上而下）：

RTOS_APP── 调 ──▶USER_Code 驱动
Main_task→Chassis_task →Tower_task →position/chassis_control/visual_identity/tower →HAL 外设
  • Chassis_task 依赖 chassis_control(运动学)、position(OPS)、visual_identity(视觉)、io_devices(LED/蜂鸣)。
  • Tower_task 依赖 tower(电机) + hcan(CAN发送) + chassis_control(d_X/d_Y 逼近量联动) + chassis_move(底盘合作抓取)。
  • Output_task 依赖 OLED_SPI 与 chassis_control(pos_x/pos_y)。
  • Main_task 是唯一定点调用所有动作函数的编排者（依赖 Output/Chassis/Tower 头文件）。
  • 全局共享数据（VIS_RX, RC_RX, SpeedTarget, pos_*, color_task, ready, chassis_mode, control_mode）在多个任务间交叉读写——这是协作（非消息传递）的核心耦合点。

12构建与运行

环境要求

  • Keil MDK-ARM（建议 UV5 及配套 ARM Compiler V5）
  • STM32F4xx 器件支持包（Pack）
  • 下载器：ST-Link / J-Link 通过 SWD 接口

步骤

  1. 用 Keil 打开 MDK-ARM/Logistics_Vehicle_F407.uvprojx。
  2. 在工程选项选择目标设备 STM32F407VETx，确认使用 AC5（V5）编译器 —— Readme.txt 提示因 FreeRTOS 兼容性需用 V5。
  3. 点击 Build (F7) 编译；若使用其他主频/时钟注意 SystemClock_Config()（HSE→168MHz）。
  4. Download (F8) 烧录，后复位运行。
  5. 上电后 OLED 显示版本；等待 ready 就绪（或遥控按键 L2 跳过等待 / 按启动按键），随后进入比赛流程或遥控模式。
运行提示：开发调试时可先以遥控模式（拨杆 L1）验证底盘/塔吊/夹爪，再切换自动模式跑完整流程。电机总开关必须先 VM_ON()（Motor_Init 中已调用）。
